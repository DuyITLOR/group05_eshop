## Detail
| ID | Test Objective | Transition Path | Expected Result |
|---|---|---|---|
| FR10-STT-12 | Chặn User/Admin hủy đơn hàng khi đã đi giao | `shipping` --(Cancel)--> `Chặn` | Hệ thống báo lỗi 400, chặn hủy đơn, trạng thái giữ nguyên là `shipping` |

## Preconditions
1. Đăng nhập tài khoản User test (`test@eshop.com` / `Test1234!`).
2. Có sẵn một đơn hàng test của User này ở trạng thái `shipping`.

## Test data
| Field | Value |
|---|---|
| Tài khoản User | `test@eshop.com` / `Test1234!` |
| Mã đơn hàng | [Lấy ID đơn hàng shipping thực tế] |

## Test steps
1. Gửi yêu cầu hủy đơn hàng qua endpoint `PUT /api/orders/:id/cancel` với header Authorization hợp lệ.
2. Kiểm tra trạng thái đơn hàng trong Database.

## Expected results
1. Response trả về HTTP status 400 Bad Request.
2. Response body chứa thông báo lỗi chặn hủy đơn hàng đang giao.
3. Trạng thái đơn hàng trong Database giữ nguyên là `shipping`.

## Actual results
1. Response trả về HTTP status 200 OK.
2. Response body: `{"message":"Order canceled successfully"}`.
3. Trạng thái đơn hàng trong Database được cập nhật thành `canceled` (Lỗi: Cho phép hủy đơn hàng đang ở trạng thái shipping).
